# Phase 1.5 — Sync test cases to a Jira Sub-task

**输入：** 按[计划模板](../e2e-workflow/references/plan-template.md)完成的本地计划，以及其中的 `Sources > Ticket`。

**输出：** 一个已回读核验的 Jira Sub-task 和本地映射，或明确的跳过、暂停、受阻或冲突。

```text
来源 Jira 工单
└── 一个普通 Sub-task：完整测试计划 + 不可变身份标记
```

每份计划只维护一个普通 `Sub-task`，不按 `TC-n` 分建工单。标题必须使用确切前缀：

```text
[Test Cases][Auto-Created] <功能标题>
```

## 1. 检查来源并校验计划

在发现或调用 Jira 工具之前，先读 `Sources > Ticket`：

- **真实 Jira 工单：** 直接进入本节的本地准备、能力检查和差异预览；不额外要求“开启同步”。用户已明确暂停时保留映射并记录暂停。
- **无来源工单：** `none`、`N/A`、空值或占位符都跳过 Jira，不发现工具、不查询、不创建对象。新计划或从未建立同步身份的计划将两个映射字段设为 `N/A`。
- **已有同步历史但来源或映射缺失：** 保留原身份和已知 key，记录受阻并按下方兼容与恢复规则处理，不能清空成 `N/A` 或新建替代身份。来源不是 Jira 时说明本 Skill 不适用，不自动改用其他系统。

计划在 `Sources` 中记录：

| 字段 | 有真实 Jira 工单 | 无工单、从未同步 |
| --- | --- | --- |
| `Ticket` | 真实 key 和可用链接 | `none` |
| `Plan sync ID` | 不可变、在该工单下唯一，例如 `<ticket-key>/<feature-slug>` | `N/A` |
| `Jira Test Cases Sub-task` | `pending` 或已核验的 Sub-task key | `N/A` |

首次准备时，核实工单与功能标识，填写唯一的 `Plan sync ID` 并将 Sub-task 映射设为 `pending`。移动文件、改标题或后续修改计划都不改变身份；已有历史但字段丢失时先恢复，不重新生成。

检查每个案例的表格行与详情一致，包含稳定 `TC-n`、简单英文 `should ...` 标题、文件、setup、编号用户步骤和具体 `expect:`。一条 TC 对应一个 test；`obsolete` 行与详情保留，ID 不重排、不复用，新 ID 大于历史最大值。`blocked` / `unverified` 及其覆盖缺口不能在同步时被删除或改成已验证。

## 2. 核实 Jira 能力

只在通过工单检查后，发现当前可用的连接器/API 并遵循实际工具 schema。读取来源工单、项目 issue type 元数据和父子关系，确认支持普通 `Sub-task`。

必须能查全来源工单下的 Sub-task、读取已有对象、完成本次需要的创建或更新，并回读核验。权限、认证、查询完整性、元数据或回读能力缺失时不写入；记录确切缺项，本地测试工作继续。

本流程管理的字段只有：创建时的类型与父项，以及标题与完整计划描述。后续只更新标题和托管的计划描述，保留人工补充、托管块外内容、状态、负责人、标签、评论和附件。不删除 Sub-task，不发评论或额外通知，不创建其他远端对象。

## 3. 对账并预览

新身份使用标记 `sprite-tester-e2e:<plan-sync-id>:test-cases`；已记录并核实的既有标记继续原样使用，不因迁移重命名。

1. 无论映射是 `pending` 还是已有 key，都查全来源工单下的 Sub-task，并精确匹配完整标记。不能只凭标题接管对象。
2. 已有 key 还须独立回读，核对 Jira 站点、父项、普通 Sub-task 类型与标记；它必须与标记搜索找到的唯一对象一致，一个 key 不能被多个计划共用。
3. 将结果分类并列出每项托管字段差异：

| 对账结果 | 分类 |
| --- | --- |
| `pending`，查全后无标记匹配，且没有未解决的既有同步历史 | `create` |
| 唯一精确匹配，需要改变标题或计划描述 | `update` |
| 唯一精确匹配，内容相同 | `no-op`；映射丢失时仍回读后恢复本地 key |
| 有明确旧映射但没有标记，且通过下方来源核验 | `migrate` |
| 多个匹配、错误父项/类型/标记、key 冲突、映射不一致或查询不完整 | `conflict`；不创建替代对象 |

旧的无标记 Sub-task 只有在这些条件同时满足时才可迁移：显式记录的 key 能读取、父项和类型正确、标题以 `[test cases]` 或 `[Test Cases][Auto-Created]` 开头、描述含精确 `Plan sync ID` 与该计划的案例 ID，而且没有已标记的兄弟对象。证据不足时停止同步，不凭近似标题认领。

预览来源工单、类型、key（或 `pending`）、完整标记、标题和描述的每一项变化。示例：

```text
CREATE SUB-TASK pending   [Test Cases][Auto-Created] <功能标题>
MIGRATE SUB-TASK <key>    添加身份标记；标题变化；计划描述变化
UPDATE SUB-TASK <key>     标题变化；计划描述变化
CONFLICT <key>           身份标记或父项不一致
```

描述应包含完整当前计划及标记；复制时排除模板说明、秘密和无关探索日志。必要附件在 Jira 不可访问时说明限制，不自动上传或扩大访问权限。

真实工单、计划认可和连接权限本身不授权远端写入。已有明确覆盖该目标与动作的授权直接沿用；缺少授权时，完成上述可审阅差异后再询问。用户拒绝或未答复时不写入；不重复确认已授权动作。

## 4. 写入、回读、更新本地

1. 写入前核对远端版本/内容是否变化；影响预览时重新对账。只执行已授权动作，`conflict` 不写入，纯远端 `no-op` 不重复写入。
2. 创建时设置普通 `Sub-task`、来源工单父项、确切标题前缀和完整计划描述加标记。迁移或更新只改变已预览的标题与托管描述，不改变父项或非托管字段。
3. 创建、更新或恢复后回读，验证父项、类型、标题、完整计划和精确标记。成功后才将核实的 key 写入 `Sources > Jira Test Cases Sub-task`；远端 `no-op` 也需这一步才能恢复丢失的本地映射。
4. 本地 key 改变了计划正文时，计算最终描述差异，在已有授权范围内补写一次并再次回读。缺少该补写授权时保留已核实 key，注明描述待同步，不声称同步完成。
5. 报告真实链接、动作和状态。只有最终本地计划与远端托管内容一致才报告完成；部分失败如实保留，不影响本地测试结果的独立判定。

## 只在兼容或恢复时读取

**此前版本的字段：** 兼容 `Remote sync` 区中的 `Plan sync ID`、`Remote test plan`、`Sync target` 和 `Sync status`。确认指向同一个 Jira 工单与普通 Sub-task 后，将已核实的身份与 key 对应回 `Sources` 字段，保留历史；key 尚未核验时先沿旧字段对账，不提前写成已核验映射。新旧字段冲突只暂停同步，不能覆盖其中一方。明确暂停继续有效；单独缺少“已开启”标记不构成新门槛。旧目标是其他系统时不自动改成 Jira。

**部分失败恢复：** 超时或响应不明时保留原 ID、标记和已知 key。下次先按同一标记查全并对账，不能直接重试创建。唯一对象即使内容相同，也回读后补回本地映射，再处理最终计划描述差异。不能确定前次动作是否成功时记录受阻，不无限重试或产生重复对象。

## 完成条件

- 无来源的新计划使用 `N/A` 映射，且没有任何 Jira 工具发现或调用。
- 有来源的计划只对应一个已核验的普通 Sub-task；父项正确，标题前缀确切，描述含完整计划与不可变标记。
- 每次写入在授权范围内，远端回读成功后才更新本地映射；最终内容一致，或未完成部分与冲突明确可见。

完成后返回 [Generate](../e2e-generate/SKILL.md) 或当前本地阶段；暂停或同步受阻不阻止可独立完成的测试工作。
