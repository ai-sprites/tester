# 将测试记录关联到 Jira

**输入：**真实测试计划或报告、目标 Jira 工单，以及本次写入范围。

**输出：**已核验的 Jira 更新与链接，或具体受阻原因。本技能按需使用，不是探索、生成或执行测试的必经阶段。

## 1. 读取目标与现有记录

通过当前可用的 Jira MCP 读取目标工单及已有相关测试记录，核对项目、工单和本次测试范围。沿用已有链接、测试对象或子任务，避免重复建项。没有目标或本次不需要同步时，交付本地结果即可。

请求已明确要求同步时，沿用该授权；仅读取需求、有 Jira 来源链接或完成测试不等于要求写入。已有明确暂停继续有效。

## 2. 准备本次需要的更新

按项目现有约定更新已有测试字段、记录或附件链接。保留其他人的内容，仅修改本次负责的部分。测试计划写明范围、步骤和预期；结果写明版本、环境、实际通过/失败/未运行、覆盖缺口和证据链接，不把探索状态当成执行结论。

默认关联已有工单；只有用户要求或项目明确规定且属于本次任务时才新建测试事项，不强制每份计划创建 Sub-task，不要求专有身份字段或统一标题。必要时先给出具体差异，缺少写入授权时再确认。

## 3. 写入并核验

使用已发现工具的真实能力和字段，在当前授权内完成更新。评论或通知仅在用户明确要求时发送，不把“关联结果”自动解释为发送消息。

写入后回读核对内容与链接。请求超时或结果未知时先查远端实际状态，不能盲目重复创建；权限、访问或目标冲突只阻止受影响的同步。本地报告保留实际远端链接、当前状态及未完成项，不另建同步台账或持续同步任务。

## 完成条件

- 更新指向正确工单，测试内容与真实计划/结果一致。
- 写入已回读核验，或明确标出尚未完成的部分。
- 交付实际链接后返回本次测试工作；同步受阻不阻止独立测试。
