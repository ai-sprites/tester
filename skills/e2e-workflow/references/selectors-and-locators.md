# 选择器与控件断言

生成或修改交互时读取。先从项目配置和现有测试发现 test ID 属性、可访问名称及组件约定，不移植其他项目的属性名、组件标签或常量。阶段入口见 [E2E 工作流](../SKILL.md)。

## 定位可观察行为

- 优先使用可稳定表达用户意图的 role/name、label 或项目约定的稳定 test ID。`getByTestId()` 的实际属性由 runner 配置决定，不能默认它等于某个自定义属性。
- 遇到重复名称，按有意义的区域、对话框、行身份或父级范围收窄；先确认唯一性。不要靠无解释的 `first()`、`nth()` 或动态样式类把歧义藏起来。
- 复用项目已有选择器与文案来源。必须使用结构选择器或自定义组件标签时，说明稳定依据；避免长 CSS 链、易变 class 子串或与行为无关的实现细节。
- 保留会在每次操作时重新查询的 Locator。不要跨重新渲染缓存 ElementHandle，也不要保留一次 `count()` 推导出的列表索引作为长期身份。数据刷新后仍需用实体身份和真实结果核对，避免定位到旧内容或另一条记录。

## 原生控件与自定义组件

原生输入值用 `toHaveValue()`，选中状态用 `toBeChecked()`，禁用/启用用 `toBeDisabled()` / `toBeEnabled()` 等语义断言。受控输入的属性文本可能与当前属性值不同，不能用 `value` attribute 替代用户实际输入值。

自定义组件先检查它公开的真实状态契约：可访问状态、内部原生控件或确实代表状态的 attribute。只有状态由该 attribute 表达时才使用属性断言，并写明原因；不要假定原生控件断言能自动识别所有自定义属性。

优先使用正常用户操作和框架 actionability 检查。强制点击或直接派发事件可能跳过用户实际无法操作的状态；仅在已有组件契约明确要求该方式时使用并说明原因，不能用它们掩盖遮挡、脱离 DOM 或控件未就绪。

每次依赖数据刷新的断言既要等待触发的请求或等效信号，又要识别对应的可见结果。具体时序见 [可靠性与就绪信号](reliability-and-readiness.md)。
