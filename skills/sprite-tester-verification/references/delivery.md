# 交付与留存规则

生成、更新、迁移或交接测试产物时读取。本文件适用于通用验证和 E2E，随完整 Skill 一起接入。

## 填写模板与沿用旧产物

- 正式功能验证、回归或验收使用[测试报告模板](../assets/templates/test-report.md)；E2E 计划使用[计划模板](../assets/templates/e2e-plan.md)。读取完整模板后再填写，新文档保留章节与适用字段；已有文档可沿用等价结构，但须覆盖模板的适用内容。
- 使用真实业务信息，无关字段写无或不适用，不编造数据、负责人、批准或执行结果。模板中的 Markdown 占位链接采用 `(<...>)`；交付文档替换为真实路径，不保留占位内容或把模板路径当成交付地址。
- 已有产物先读取，局部更新受影响内容并保留有效历史。说明哪些旧依据已替代、哪些结论仍适用或需要重验；未重新验证的旧结果不能冒充当前证据。
- 单次简单检查或小型答疑可在回复中保留完整适用信息，不强建空报告。不能保存正式产物时说明限制和未完成部分，不声称已交付。

## 放在哪里

沿用已明确的资料来源仓库（host repo）与产物业务仓库，两者可以不同。首次接入只将未明确的仓库选择合并询问一次，允许“暂无/稍后配置”并先完成接入；已答或暂缓的项不重问。真正使用时再补必需版本、功能或文件，产物目录固定为所选业务仓库的 `docs/tester/`，不另问任意保存目录。

| 内容 | 位置与处理 |
| --- | --- |
| 测试计划、报告、复现记录 | 业务仓库 `docs/tester/`，可按功能建子目录，例如 `docs/tester/<feature-id>/e2e-plan.md` 和 `verification.md` |
| 支持结论的日志、截图、trace 和附件 | 同一功能目录的 `evidence/`；先脱敏，遵守项目保密、忽略与 CI artifact 规则，交付实际可访问路径 |
| 产品代码、测试代码、POM、fixture、辅助函数、测试配置 | 工程原生目录，遵循现有组织方式 |
| runner 自动生成的中间输出 | 原配置位置；必要证据整理到 `docs/tester/`，无法安全导出的原始证据注明来源与访问限制 |
| 角色和 Skill 安装资源 | 原安装位置，业务产物不写入 Skill 目录 |
| 上游资料 | 按真实位置读取；跨 Git 原始导出包按下节保存 |

认证状态、密码、令牌和敏感原始数据不进入正式报告或提交。只清理本次产生且无留存价值的 scratch、探测脚本和重复输出，保留用户原文件与支持失败判断的证据。

旧位置散落的本职产物先读取，保留内容迁入 `docs/tester/`，不得直接覆盖目标同名文件；迁移后同步相关引用和已有索引。迁移不改变工程代码、安装资源和上游资料的位置。

## 链接与索引

交付真实链接、所属仓库、相对 Git 根路径及依据版本。Markdown 链接相对所在文档，索引链接相对索引；链接可达或文件在同一提交，不等于内容一致或已获批准。

项目已有资料索引时，随本职产物创建、更新、移动或删除同步真实链接和简要说明，移除失效条目并保留其他内容，只登记存在的文件。没有索引则不强建全局登记，也不要求凑齐其他角色产物。

可选 `artifacts.json` 使用 `features[功能标识].documents` 登记 `kind: "verification"` 及相对资料 Git 根的 `path`（例如 `docs/tester/<feature-id>/verification.md`），或外部 `url`；附件单独列出。外部资料保留主源与实际版本。

## 跨 Git 读取与留存

普通本地资料和纯角色接入不需要 artifact-bridge。当前任务确需跨 Git 读取、固定版本、比较或导出留存时，复用已有 bridge；缺失或能力不足时，按其[README](https://github.com/ai-sprites/artifact-bridge)和[接入手册](https://github.com/ai-sprites/artifact-bridge/blob/main/docs/installation.md)补齐同一明确版本的完整 Skill，适配当前客户端已有目录，保留自定义并告知用户，无需另索安装确认。用户已拒绝或权限、网络不足时说明限制，继续独立部分。

使用当前采用版本的[读取与留存规则](https://github.com/ai-sprites/artifact-bridge/blob/main/skills/sprite-artifact-bridge/references/commands.md)和[索引格式](https://github.com/ai-sprites/artifact-bridge/blob/main/skills/sprite-artifact-bridge/references/index.md)，核对以下事项：

1. **选择完整。** 正文和必要附件逐个选入。链接不会自动展开，目录不会递归读取；外链只保留地址，需要内容留存时另行导出并登记真实文件。
2. **版本可获取。** 每个来源的正文、索引和附件进入选定且接收方可获取的提交。在已有授权内完成 Git 协作；未提交或未推送如实说明。bridge 不替上游提交或推送，也不自动追踪新版本。
3. **导出有原始映射。** 实际检查完整性、错误和逐项状态。原始导出包（资料副本、附件、`manifest.json`）保存到业务仓库 `docs/artifact-bridge/`，可按功能使用 `docs/artifact-bridge/<feature-id>/`；默认目录为 `docs/artifact-bridge/<sourcehash>/<selectionhash>/<commit>/`。本角色据此生成的报告和加工附件仍放 `docs/tester/`。保留来源仓库、完整提交、源文件与留存位置的映射。
4. **交接结果真实。** 交付实际目录，将缺文件、超限、外链等未留存项单列。区分已保存、已提交、远端可获取和已导出；不能落盘或访问时明确说明。仅针对当前必需的来源、业务仓库、登录或授权提出具体问题，其余工作继续。
