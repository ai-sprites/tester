# 可选：把计划同步到来源工单

保留本地计划作为完整可交接输入；按当前项目约定，把一份计划对应到一个远端测试计划对象。Jira 的普通 Sub-task 是可用方案，不是角色的必需依赖。其他系统仅在目标对象、身份及工具能力已明确时采用同样的核对流程，不把普通 PR 自动转换成 Jira 工单。

## 入口与权限

先读取计划 `Sources` 中的 `Ticket`、`Sync target`、`Plan sync ID` 和 `Remote test plan`。兼容旧计划的 `Jira Test Cases Sub-task` 字段：把真实 key 作为待核实的既有映射保留，缺少 `Sync target` 不等于从未同步。新旧字段若冲突，只暂停同步并核对；本地迁移字段时保持原 ID、key 及身份标记，不覆盖历史。

下述 N/A 初始化只适用于从未建立同步身份的新计划。已有 ID/key 的计划即使来源字段缺失、临时断连、用户暂停或关闭同步，也保留映射与已知标记，记录暂停/受阻原因；不能借清空身份重新创建。

- 没有真实工单（none、N/A、空值或占位符）：新计划关闭同步、映射为 N/A；旧计划保留身份并标受阻。不发现或调用工单工具。
- 有真实工单但同步未开启：新计划保留来源、映射为 N/A；旧计划保留映射并记录暂停。继续本地工作，不自动创建远端对象。
- 已请求/配置同步：先读取真实来源和能力，准备具体差异。有源工单或用户认可本地计划，本身不等于授权远端写入。当前会话已明确授权该目标、对象和字段的同步动作时直接沿用；否则在具体差异可审阅后，只就缺少的远端写入授权提问。

读取来源工单以理解需求不等于执行同步。单独的连接、发现、迁移 Skill 或安装请求都不能授权发送评论、消息或创建其他事项。

## 计划身份与托管范围

每个开启同步的计划有一个不可变 `Plan sync ID`，可使用含来源系统/项目、工单及功能标识的稳定值；本地文件移动或标题修改不改变 ID。首次生成是普通本地步骤，已有 ID 不覆盖；迁移时不能猜测或重新生成已有远端身份。

默认身份标记为 `sprite-tester-e2e:<plan-sync-id>:test-cases`，必须原样保留在远端描述中。目标项目已有其他稳定标记时记录并继续使用，不悄悄重命名。`Remote test plan` 为 `pending` 或核实后的 key/URL；每份计划只有一个映射，每个远端对象也不能被不同计划共用。`TC-n` 独立于远端对象，不为每个案例创建子任务。

Jira 适配：从元数据验证普通 Sub-task 的实际类型 ID 和父工单能力，创建在真实来源工单下面。标题按项目约定，可默认 `[Test Cases] <功能标题>`；不把任何标题前缀当作身份。创建时管理父项、类型、标题和描述，之后只管理标题与计划描述；保护状态、负责人、标签、评论、附件及非托管内容。不要替项目安装测试管理插件或选择其他 issue 类型凑结果。

## 校验与对账

1. 先完成本地计划校验：TC 无重复或历史复用，表格与详情一致，obsolete 行保留，blocked/unverified 明示。模板中的说明、秘密、内网凭据或无关探索日志不应复制到远端。
2. 使用当前真正可用的连接器/API 能力，不写死发现函数名。核实可读取来源、分页查全相关子对象、查询/更新/创建所需类型并回读。缺权限、元数据、必要查询或验证能力时只报告同步受阻，继续本地工作。
3. 无论映射是 pending 还是已有 key，都在来源工单下查全候选并精确核对标记。零匹配且 pending 才可准备创建；一个匹配可恢复映射；多个匹配是冲突。标题相同不足以接管。
4. 已有 key 必须单独回读并验证来源系统、父项、类型、标记，与唯一标记匹配必须是同一对象。不存在、父项错误、类型错误、marker 不符、key 被其他计划使用或查询不完整时停止该同步，不能另建一份“修复”。
5. 无标记的旧映射只有在显式 key、正确父项/类型、精确 Plan sync ID 与案例 ID 等来源证据均匹配，且没有已标记兄弟对象时才可提出迁移。说明具体迁移差异；证据不足不接管。旧标记迁移同样要证明来源，不能只凭标题。
6. 比较当前计划和托管字段，归类 `create`、`migrate`、`update`、`no-op` 或 `conflict`。远端有人修改或含非托管正文时先保留内容并列差异，不能用整段替换删掉人工补充；必要时明确托管块边界再同步。

## 预览、应用与恢复

预览列出来源、对象类型、目标 key（或 pending）、完整标记、标题及描述每项变化。描述必须包含完整计划，包括 active/obsolete、未验证和未覆盖部分；托管块外的人工内容保持原样。计划中的内部附件链接若远端不可访问，明确可达性限制，不为了同步自动上传附件或扩大访问权限。

执行前重新核对远端版本/当前内容，若预览后发生影响托管字段的修改就重新对账。只执行已授权的动作；no-op 不写，冲突不写，不发送评论或额外通知。

创建或更新后回读并核对父项、类型、标题、完整计划与标记。恢复唯一匹配的既有对象时也要回读验证，即使远端托管字段为 no-op，仍可在验证后仅修复本地映射。只有成功验证后才把 key/URL 写回本地；因映射改变计划正文时，重新计算必要描述差异，在同一次已授权同步范围内补写最终描述并再次回读，确认两边一致。没有该写入授权则保留已核实 key，明确描述尚未同步，不伪称两边一致。

超时、响应不明或本地写回失败时保留部分失败状态。再次尝试前先按同一标记对账，绝不直接重复创建；若缺少判断前次动作结果的能力，暂停同步并说明所缺证据。不得无限重试、删除远端对象或另建对象绕过冲突。

交付真实远端链接、已验证状态和未完成部分；同步失败不改写自动化测试结果。返回[工作流](workflow.md)继续独立本地任务。
