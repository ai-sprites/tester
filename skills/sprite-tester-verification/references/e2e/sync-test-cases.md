# Phase 1.5 — Sync（可选）

**输入：** 完整本地计划、真实来源工单，以及同步请求或已开启的同步约定。

**输出：** 一份计划对应一个已回读核验的远端对象；失败时保留可恢复的本地映射。

Jira 的默认结构如下。其他系统仅在项目已明确对象类型、身份规则和工具能力时沿用其约定，不自动选择替代对象。

```text
来源工单
└── 一个普通 Sub-task：完整测试计划 + 稳定身份标记
```

## 1. 判断是否同步

读取 `Sources > Ticket`，再读取计划末尾 `Remote sync` 中的同步字段。兼容字段仍在旧 `Sources` 中的计划，以及旧名 `Jira Test Cases Sub-task`。

| 当前情况 | 动作 |
| --- | --- |
| 无真实来源工单（none、N/A、空值、占位符） | 跳过，不发现或调用工单工具 |
| 有来源工单，但未请求或开启同步 | 继续本地工作，不创建远端对象 |
| 同步已开启或用户要求同步 | 进入下面的对账与预览 |
| 已有同步历史，但来源/映射缺失、断连或用户暂停同步 | 保留已有身份，记录受阻或暂停；继续本地工作 |

新计划从未同步时可以省略可选区，或把 `Sync target` 写 none、映射写 N/A。**已有 `Plan sync ID`、key 和标记不得因暂停、断连或字段缺失被清空。** 新旧字段冲突时只暂停同步，不能另建对象解决冲突。

## 2. 校验计划和身份

首次开启同步且从未建立过身份时，核实来源工单和目标后，在本地初始化同步区：填写 `Sync target`，生成唯一的 `Plan sync ID`（可由来源系统、工单与功能标识组成），将 `Remote test plan` 设为 pending，然后进入对账。这个本地准备步骤不创建远端对象；已有同步历史但字段丢失时走恢复流程，不生成新身份。

- 用例 ID 不重复、不复用；表格与详情一致，obsolete 历史及 blocked/unverified 缺口完整保留。
- 一份计划有一个不可变 `Plan sync ID`，移动文件或修改标题不改变它；一个远端对象不能被多个计划共用。
- 默认标记为 `sprite-tester-e2e:<plan-sync-id>:test-cases`。已有标记继续原样使用，不因迁移重命名。
- `Remote test plan` 是 pending 或已核验的 key/URL；不为每个 TC 创建子任务。

使用实际可用的连接器/API，确认能读取来源、查全相关子对象并回读结果，以及完成本次所需的创建或更新。Jira 需从元数据核实普通 Sub-task 类型及父项关系。缺少必要权限、查询或回读能力时不写入。

## 3. 对账并预览

无论本地是 pending 还是已有 key，都查全来源工单下的候选，精确匹配身份标记；不能只凭标题接管对象。已有 key 还须独立回读，核对系统、父项、类型和标记，与搜索结果必须一致。

| 对账结果 | 分类 |
| --- | --- |
| pending，查全后没有标记匹配 | create |
| 唯一匹配，已有托管内容需要变化 | update |
| 唯一匹配，内容一致 | no-op；本地映射丢失时仍可核验后恢复 |
| 多个匹配、错误父项/类型/标记、key 冲突或查询不完整 | conflict；停止同步，不创建替代对象 |
| 有明确旧映射，但没有新标记 | 仅按下方旧映射规则评估 migrate |

预览来源、类型、key（或 pending）、完整标记、标题和描述的每一项变化。Jira 新子任务标题沿用项目约定；无约定时使用 `[Test Cases][Auto-Created] <功能标题>`。已有对象保持已采用的标题约定。

创建时管理父项、类型、标题和描述；之后只更新标题及计划描述。描述包含完整当前计划，保留人工补充和托管块外内容；状态、负责人、标签、评论和附件不在修改范围。

工单来源、计划认可和连接权限本身不授权远端写入。已有明确覆盖该目标与动作的授权直接沿用；缺少授权时，在上述差异可审阅后再询问。无需重复确认已授权动作。

## 4. 写入、回读、更新本地

1. 写入前核对远端版本/内容是否变化；影响预览结果时重新对账。
2. 只执行已授权动作。no-op 和 conflict 不写远端，不删除对象、不加评论或额外通知。
3. 创建、更新或恢复后回读，验证父项、类型、标题、完整计划及标记，再保存本地 key/URL。
4. 本地映射改变计划正文时，计算最终描述差异，在同一次已有授权内补写并再次回读；没有所需授权则保留已核实 key，注明描述待同步。
5. 报告真实链接与状态。只有两边最终内容核验一致才报告同步完成；同步失败不改变自动化测试判定。

内部附件链接在远端不可访问时说明限制；不自动上传附件或扩大访问权限。复制计划时排除模板说明、秘密和无关探索日志。

## 只在迁移或恢复时读取

**旧映射迁移：** 显式 key、正确父项/类型、精确 Plan sync ID 和案例 ID 等来源证据必须一致，且不存在已标记的兄弟对象，才可提出 migrate。预览标记变更；证据不足不接管，不能凭标题认领。

**部分失败恢复：** 超时或响应不明时保留原 ID、标记和已知 key。下次先按同一标记对账，不能直接重试创建。唯一对象与内容一致时，即使远端 no-op，也回读后补回本地映射；再按第 4 步处理最终正文差异。无法判断前次动作是否成功时暂停同步，不无限重试。

**完成：** 一个验证后的映射，或明确暂停/受阻/冲突及未完成项。返回 [Generate](generate.md) 或当前本地阶段继续。
