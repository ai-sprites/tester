# 接入当前项目的约定

开始探索、生成或修复 E2E 前读取本文件。将实际发现写入本次计划的环境、执行方法或备注，后续复用同一依据；不要为接入工作另造一套测试框架。阶段入口见 [E2E 工作流](workflow.md)。

## 从哪里发现

按当前请求和项目指令，检查适用的 `AGENTS.md`、README、包管理器与锁文件、测试配置、CI 配置以及邻近测试。需要确认：

| 项目事实 | 影响的决定 |
| --- | --- |
| 被测仓库、版本、应用入口和可访问环境 | 探索与验证针对哪个真实版本 |
| 测试框架、安装版本、包管理器、现有 scripts | 可执行的列举、单例、分组和格式检查命令 |
| 测试发现规则、项目/浏览器矩阵、setup/teardown 依赖 | 文件位置、筛选方式、登录与清理顺序 |
| fixtures、页面对象或现有辅助层、可复用常量 | 导入来源、状态隔离、交互代码的归属 |
| test ID 属性、稳定 role/name、文案来源 | 选择器与断言是否匹配实际界面 |
| 环境变量、认证状态、数据准备及忽略规则 | 哪些配置能沿用、哪些内容不能提交 |
| CI 的分片、并发、重试、报告和 trace 配置 | 本地执行与 CI 结果如何比较 |

命令来自实际配置或已经核实的项目说明；示例路径与占位项目名不能直接当成命令执行。不存在某个命名的配置文件、登录项目、POM 或私有 registry，不构成缺陷，也不应据此新建它。

## 代码组织与产物位置

- 可执行 spec、fixtures、页面对象、辅助函数和测试配置保留在工程原生目录，遵循邻近代码的导入与分组方式。有扩展的 `test` fixture 时复用它；没有时使用框架原生入口，不强建空封装。
- 在已有页面对象或交互辅助层中复用交互；业务断言留在测试中，使失败能对应计划结果。不为一次简单交互新增整套 POM，也不把原项目的 fixture 或常量名移植过来。
- 测试标题沿用项目语言和命名方式，与计划逐字对应；同一用例使用稳定 `TC-n`，不要靠修改标题或重新编号隐藏历史。
- 正式计划、报告、复现记录和已选择保留的证据保存到业务仓库 `docs/tester/<feature-id>/`。链接指向真实产物；已有文件先读后局部更新，不覆盖用户同名文件。
- 探索 scratch 使用已验证可用的忽略目录或安全临时目录，并能被所选 runner 显式运行。只清理本次创建的 scratch；不能删除已有报告、截图、trace 或整个共享临时目录。
- 工程 runner 自动生成的中间输出可留在其配置位置；需要支撑交付结论的日志、截图、trace 等经脱敏后留存到 `docs/tester/<feature-id>/`，更新引用。不要把秘密复制进正式证据。

执行与留存分别见 [CI 与执行](ci-execution.md)、[认证与环境](auth-and-environment.md)；交互规则见 [选择器](selectors-and-locators.md)。
