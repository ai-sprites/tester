# 接入手册：sprite-tester

用户粘贴 [README 中的接入说明](../README.md)，由 AI 按以下步骤完成。接入角色和 Skill 不等于执行测试或创建业务文档。

## 1. 确定客户端与资源版本

根据当前会话和项目识别客户端，沿用它支持的接入方式；只有不确定且影响接入时才查证或询问。

从同一明确版本读取 README 资源清单、[角色定义](../templates/agent.md)和完整 [sprite-tester-verification](../skills/sprite-tester-verification/SKILL.md) 目录。网页来源先固定到完整 Git 提交，本地未提交内容如实标注；源文件读不到就说明缺项，不自行编写替代品。

角色与本职 Skill 默认一起接入，也可单独使用 Skill。用户明确只要职责定义时说明未带入执行能力；其他专项 Skill 按明确请求或实际需要选择。

## 2. 完整放置，保护已有内容

原样复制角色正文、Skill、工作流、模板和随附文件，保持资源名称与内部相对目录，只适配客户端必要的文件位置、元数据格式和入口引用。专业内容不删改，项目已有规则与用户自定义保留；实际执行读取对应 Skill。

完整目录包括 `SKILL.md`、`references/` 和 `assets/`。E2E 探索、计划、可选同步、生成、执行修复及配套参考已在同一个本职 Skill 内，按任务读取；不能只复制入口，也不另装多个阶段 Skill。

已有相同内容直接复用，安装位置沿用现有约定，实质冲突只处理或询问相关部分。接入本身不填写业务模板、不建安装登记，也不配置业务登录、工单连接、测试流水线或调度。

## 3. 明确资料和产物仓库

资料来源仓库（host repo）与产物业务仓库可以不同。已有选择直接沿用，未明确的合并用白话问一次，允许稍后确定并先完成接入；实际使用时再补必需版本和文件。产物目录固定为所选业务仓库的 `docs/tester/`，无须另选目录。

产物位置、旧文件迁移和跨 Git 规则见[交付与留存](../skills/sprite-tester-verification/references/delivery.md)。本地资料直接使用；确需跨 Git 读取、固定版本、比较或导出时才复用或补齐完整 artifact-bridge Skill 并告知用户，无需额外安装指令。已拒绝或条件不足时说明限制，继续独立部分。

## 4. 核对并说明接入结果

核对实际文件、正文完整性和相对引用，按现场环境验证加载情况。简明说明采用版本、保存位置和调用方式，区分“已保存”“已加载”“已执行”。

客户端确需用户亲自完成的加载步骤再列出，没有就不加。只有聊天权限时可先在本会话使用，明确未写入项目及尚未完成的部分。

## 已有内容与后续维护

追加或更新时完整采用同一版本，补齐旧版缺少的本职 Skill，保留自定义和未选资源。移除只处理用户指定范围，保护自定义及仍被引用的文件。涉及业务产物迁移时按交付规则同步引用和已有索引，不顺带改动无关资源。
