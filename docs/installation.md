# 接入 tester

完整接入包含角色说明、一般测试方法和五个同级 E2E Skill，不把阶段合并。

## 1. 固定版本，读取完整资源

先识别当前客户端和项目已有目录。从同一明确版本读取 README 资源清单、[角色定义](../templates/agent.md)、[一般测试方法](testing.md)，以及下面五个完整目录：

- [e2e-workflow](../skills/e2e-workflow/SKILL.md)
- [e2e-explore](../skills/e2e-explore/SKILL.md)
- [e2e-sync-test-cases](../skills/e2e-sync-test-cases/SKILL.md)
- [e2e-generate](../skills/e2e-generate/SKILL.md)
- [e2e-heal](../skills/e2e-heal/SKILL.md)

网页来源固定到完整 Git 提交，再取同批文件；本地未提交内容如实标注。源文件无法读取就说明缺项，不编造替代版本。

## 2. 保持五个同级 Skill 完整落盘

把五个目录放进同一个客户端 Skill 根目录。保留每个 `SKILL.md` 的名称和完整正文，以及 `e2e-workflow/references/` 的所有参考、模板。阶段之间通过同级相对路径引用；不能只复制一个阶段入口而遗漏共享依赖，也不能重新塞进一个聚合 Skill。

角色说明及 `docs/testing.md` 一起放入客户端合适的角色/文档位置。只适配必要的目录、元数据和入口引用，保持一般测试方法可达；正文原样保留，不摘要替代。E2E Skill 彼此引用保持原相对结构。

已有同名技能先比较来源和内容，保护用户自定义；实质冲突只处理相关部分。默认完整接入角色和五个 Skill；用户明确只要角色或部分能力时说明实际安装范围，并补齐其已授权且必需的同级依赖。其他专项能力按实际任务选择。

接入本身不执行测试、不填写业务模板、不建安装登记，也不配置账号、工单连接、CI、定时任务或外部通知。

## 3. 升级旧聚合版

从旧 `sprite-tester-verification` 升级时：

1. 先完整安装并核验五个 Skill 和共享参考。
2. 将旧阶段调用改到对应独立 Skill；一般测试职责使用随附角色说明，不再经过旧聚合入口。
3. 对照旧目录保留用户自定义，按职责迁到对应 Skill 或角色文档；无法自动合并的部分保留原文并说明冲突。
4. 引用验证通过后移除无定制的旧聚合目录。有未迁移自定义时，将旧原文移出 Skill 自动发现目录归档，防止两个入口同时生效；不能直接丢弃用户内容。

不删除业务报告、测试代码、项目配置或其他 Skill。已有测试计划的稳定 TC、同步 ID 和工单映射继续保留。

## 4. 资料、产物和加载检查

资料来源仓库与产物业务仓库可不同，已有选择沿用；缺项合并用白话问一次，允许稍后配置并先完成接入。真正使用时再补必需版本和文件。产物固定放业务仓库 `docs/tester/`，不用另选任意目录。

旧产物迁移、模板、索引和跨 Git 留存按 [交付规则](../skills/e2e-workflow/references/delivery.md)执行。普通本地资料不需要 artifact-bridge；确需跨 Git 时才复用或补齐完整 bridge 并告知用户，保留已有授权、拒绝和访问边界。

核对五个 `SKILL.md`、完整共享参考、角色和一般测试说明的真实文件与相对引用，再按客户端能力检查加载情况。说明版本、位置、调用方式，区分已保存、已加载和已执行。只有聊天权限时可在会话中使用，明确未写入项目；确需用户完成的加载步骤再列出。

## 已有内容与后续维护

更新时采用同一明确版本，完整保留五个独立 Skill 的结构与正文，保护自定义和未选资源。移除只处理用户指定范围，先核对依赖与引用；业务产物迁移须保留内容、避免覆盖并同步已有索引。
