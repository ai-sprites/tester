# 测试产物如何交接

正式功能验证、回归或验收会保存测试报告；E2E 还会交付计划与对应测试。报告说明验证了什么、真实结果、失败证据、未覆盖项和结论。单次简单检查可直接在回复中说明。

## 默认位置

| 产物 | 保存位置 |
| --- | --- |
| 计划、报告、复现记录 | 业务仓库 `docs/tester/`，可按功能建子目录 |
| 必要日志、截图、trace、附件 | 同一功能目录的 `evidence/`，按项目要求脱敏和留存 |
| 测试代码、fixture 与可执行配置 | 工程已有测试目录 |

已有散落测试产物会在保留内容的前提下迁入角色目录，避免覆盖同名文件，并更新相关引用和已有索引。上游资料与安装资源保持原位。

## 跨仓库资料

资料来源仓库和产物业务仓库可以不同，沿用已明确的选择；尚不需要的可以稍后配置。本地文件直接读取，确需跨 Git 固定版本、比较或导出时才复用或补齐 artifact-bridge，并告知你。

bridge 原始导出包放在 `docs/artifact-bridge/`，测试报告和加工证据仍放在 `docs/tester/`。交接会提供真实路径、来源版本和未留存项，区分“已保存”“已提交”“远端可获取”“已导出”。未运行的检查不会记为通过。

AI 执行时的完整模板、目录、旧产物迁移、索引和跨 Git 规则集中在 [共享交付与留存规则](../skills/e2e-workflow/references/delivery.md)。
